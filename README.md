# textbin

Внутренний сервис «залил текст — получил URL». Для промптов, инструкций ИИ и скиллов,
которые не хочется держать в случайных файлах.

Без авторизации, без БД, без зависимостей: один `server.js` на встроенном http-модуле Node.

Прод: **https://kvadratnikitosa.ru/bankiru/**

## Запуск локально

```bash
node server.js                                  # http://localhost:8080, данные в ./data
PORT=8090 BASE_PATH=/bankiru node server.js     # как на проде, на подпути
```

| Переменная | По умолчанию | |
|---|---|---|
| `PORT` | `8080` | порт |
| `DATA_DIR` | `./data` | каталог с текстами |
| `BASE_PATH` | пусто | префикс подпути, например `/bankiru` |

## URL-схема

| URL | Что делает |
|-----|-----------|
| `/bankiru/` | главная: вводишь свой раздел → попадаешь в него |
| `/bankiru/frolovn/` | список твоих текстов + кнопка СОЗДАТЬ |
| `/bankiru/frolovn/new` | форма создания: `path` + текст |
| `/bankiru/frolovn/update-tokens-ui-kit` | сам текст |
| `.../update-tokens-ui-kit/edit` | правка |
| `.../update-tokens-ui-kit/raw` | всегда `text/plain` |
| `/healthz` и `/bankiru/healthz` | `ok` для проб |

По основному адресу отдаётся **разное в зависимости от `Accept`**: браузеру — страница
с кнопкой «Редактировать», `curl` и ИИ-агенту — чистый `text/plain`. Один и тот же адрес
годится и человеку, и в `WebFetch`.

```bash
curl -X PUT --data-binary @instruction.md https://kvadratnikitosa.ru/bankiru/frolovn/update-tokens-ui-kit
curl https://kvadratnikitosa.ru/bankiru/frolovn/update-tokens-ui-kit
```

## Как хранятся тексты

Истина — **в оперативной памяти процесса**: `Map` вида `раздел → path → текст`, все
чтения идут из неё, диск на чтение не дёргается. Каждая запись **дублируется в файл**,
чтобы пережить рестарт; при старте всё читается обратно в память (в логе видно
`загружено текстов: N`).

```
/root/dev/textbin-data/
  frolovn/
    update-tokens-ui-kit.md
    .history/
      update-tokens-ui-kit/2026-09-07T14-04-35-178Z.md   # версия до последней правки
```

Обычные `.md`: бэкап — `tar` или `./deploy.sh --backup`, посмотреть — `cat` на сервере.
Авторизации нет, поэтому перед каждой перезаписью и удалением предыдущая версия
падает в `.history/`.

Следствия схемы «память + дубль»:

- Если правишь файл на сервере руками — нужен `./deploy.sh --restart`, иначе в памяти
  останется прежний текст и он же перезапишет файл при следующей правке через UI.
- Только один процесс (`exec_mode: 'fork'`, `instances: 1`). Реплики разошлись бы
  по своим копиям памяти.
- Не смог записать файл — запрос отдаёт 500, чтобы не было текста, который исчезнет
  при рестарте.

## Деплой

Сервер `root@193.124.203.221`, node через nvm, процессы под pm2 — как у kvadrat.
Порт 8090 (3500 и 81 заняты kvadrat), сервис отдаётся на подпути `/bankiru`.

```bash
./deploy.sh --setup     # один раз: pm2, каталог данных, автозапуск, проверка порта
./deploy.sh             # залить (rsync) + pm2 startOrRestart + проверка healthz
./deploy.sh --nginx     # напечатать location-блок для nginx
./deploy.sh --logs      # живые логи
./deploy.sh --status    # что крутится + сколько текстов
./deploy.sh --backup    # скачать тексты с сервера в ./backup
./deploy.sh --dry-run   # посмотреть, что уедет
```

Сборки нет — зависимостей ноль, уезжает сам `server.js`. Раскладка на сервере:

```
/root/dev/textbin/        server.js, package.json, ecosystem.config.cjs
/root/dev/textbin-data/   тексты — вынесены из деплой-папки, чтобы rsync --delete их не снёс
```

Последний шаг делается руками один раз: вставить блок из `./deploy.sh --nginx` в
server-блок `kvadratnikitosa.ru` (тот, что слушает 443) и `nginx -s reload`.
Префикс не срезается — сервис знает про него сам через `BASE_PATH`.

`deploy/reference/` — исходные файлы деплоя kvadrat, по которым это сделано.

## Ограничения (осознанные)

- **Нет авторизации** — как и просили. Любой, кто откроет адрес, может править и удалять
  чужие тексты; страховка только `.history/`. На публичном домене открытый анонимный
  pastebin со временем находят боты и набивают спамом — если это случится, лечится
  basic-auth на прокси только для записи, `limit_req` или доступом по IP.
- Лимит текста 2 МБ (`MAX_BODY`).
- Разделы (`a-z0-9-`, до 32) и path (`a-z0-9._-`, до 64) валидируются регулярками —
  этим же закрыт обход каталогов.
- `new`, `raw`, `edit`, `healthz` зарезервированы и не могут быть именем текста.
- Нет поиска по текстам и нет UI для `.history/`.
